# std::async

可以把 `std::async` 看作一个**异步函数调用包装器**。它的核心目的是：**让你像调用普通函数一样调用一个函数，但这个函数会在后台异步执行，不会立即阻塞你的当前线程。**

它通过返回一个 `std::future` 对象来实现这一点。这个 `future` 对象就像是你的“收货凭证”，你可以在未来的任何时候凭这个“凭证”去获取函数的执行结果。

`std::async` 的基本调用形式如下：

```cpp
#include <future>

// 函数形式
std::future<ReturnType> fut = std::async(Function, Args...);

// 常用形式：指定启动策略
std::future<ReturnType> fut = std::async(LaunchPolicy, Function, Args...);
```

*   `ReturnType`：你所要调用的那个函数的返回类型。
*   `LaunchPolicy`：启动策略。
*   `Function`：要异步执行的可调用对象（函数、函数指针、Lambda表达式、函数对象等）。
*   `Args...`：传递给 `Function` 的参数。

## 示例

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

int calculate() {
    std::this_thread::sleep_for(std::chrono::seconds(2)); // 模拟耗时计算
    return 42; // 返回答案
}

int main() {
    // 启动异步任务！
    std::future<int> result_future = std::async(std::launch::async, calculate);

    // 主线程不会被阻塞，可以继续做其他工作
    std::cout << "Main thread is doing some other work..." << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Main thread work done. Waiting for result..." << std::endl;

    // 需要结果时，用 get() 获取。这会阻塞，直到 calculate() 执行完成。
    int result = result_future.get();
    std::cout << "The answer is: " << result << std::endl;

    return 0;
}
```
**输出可能是：**
```
Main thread is doing some other work...
Main thread work done. Waiting for result...
// (大约又过了1秒)
The answer is: 42
```

## 启动策略 (Launch Policy)

它决定了函数**何时**、**在何处**执行。

### 1. `std::launch::async` (异步启动)
*   **行为**：强制要求函数**必须**在一个**新的线程**中异步执行。
*   **保证**：函数肯定会并发执行，提供了真正的异步性。
*   **何时使用**：当明确希望函数在后台并发运行时使用。这是最常用、行为最确定的策略。

```cpp
// 明确指定在新线程中异步执行
auto fut = std::async(std::launch::async, myFunction);
```

### 2. `std::launch::deferred` (延迟启动)
*   **行为**：函数**不会立即执行**。它的执行会被**延迟**到将来在返回的 `future` 上第一次调用 `get()` 或 `wait()` 时。
*   **关键点**：**并且，它会在调用 `get/wait` 的同一个线程中同步执行**，而不是在新线程中。
*   **何时使用**：当希望惰性求值，或者想手动控制函数执行时机时使用。它实际上没有创建新线程。

```cpp
// 延迟执行
auto fut = std::async(std::launch::deferred, myFunction);

// ... 很多其他代码 ...

int result = fut.get(); // 函数在这里被同步调用和执行！
```

### 3. 默认策略 (`std::launch::async | std::launch::deferred`)
*   **行为**：如果不指定策略，这就是默认行为。它允许 `std::async` 的实现自行选择使用 `async` 还是 `deferred` 策略。
*   **问题**：这意味着函数的执行是**不确定的**。它可能在新线程中运行，也可能被延迟到 `get()` 时同步运行。这取决于库的实现和系统负载。
*   **建议**：**为了代码的可预测性和可维护性，最好总是显式指定启动策略**。绝大多数情况下，需要的都是 `std::launch::async`。

```cpp
// 默认策略（不推荐，因为行为不确定）
auto fut = std::async(myFunction);

// 推荐：总是显式指定
auto fut = std::async(std::launch::async, myFunction);
```

## 异常处理

`std::async` 还有一个巨大优势：它能自动将函数中抛出的异常传递到主线程。

在普通的多线程编程中，如果工作线程抛出异常且未被捕获，程序会直接调用 `std::terminate` 崩溃。但 `std::async` 将异常捕获并存储在其共享状态中。当你调用 `future.get()` 时，这个异常会在主线程中**被重新抛出**。这样就可以用 `try-catch` 块来处理异常了。

```cpp
#include <iostream>
#include <future>
#include <stdexcept>

void mightThrow() {
    throw std::runtime_error("Something went wrong in the async task!");
}

int main() {
    auto fut = std::async(std::launch::async, mightThrow);

    try {
        fut.get(); // 在这里，异常从异步线程被传递到主线程
    } catch (const std::exception& e) {
        std::cout << "Caught an exception from the async task: " << e.what() << std::endl;
    }

    return 0;
}
```

## std::async vs. std::thread

| 特性           | `std::async` + `std::future`                         | 直接使用 `std::thread`                                           |
| :------------- | :--------------------------------------------------- | :--------------------------------------------------------------- |
| **获取返回值** | **简单直接**，通过 `future.get()`                    | **非常麻烦**，需要手动设计通信机制（如全局变量、Promise/Future） |
| **异常处理**   | **自动传递**，可用 `try-catch` 捕获                  | **线程内部必须自己处理**，否则导致整个程序终止                   |
| **线程管理**   | **自动管理**，库负责线程的创建和销毁（可能复用线程） | **手动管理**，需要自己 `join` 或 `detach`，容易出错              |
| **设计理念**   | **基于任务**：关注“要做什么”和“结果是什么”           | **基于线程**：关注“如何创建和管理执行流”                         |

**简单来说：`std::async` 是一个更高级的抽象，它帮你处理了线程管理的底层细节，让你更专注于任务和结果本身。**

## 总结与最佳实践

1.  **把它当作异步函数调用**：用它来包装任何你希望在后端执行的函数。
2.  **始终显式指定启动策略**：为了代码行为清晰可预测，总是使用 `std::launch::async`。
    ```cpp
    // 推荐做法
    auto myFuture = std::async(std::launch::async, myFunction, arg1, arg2);
    ```
3.  **记得获取结果**：即使你不关心函数的返回值，也应该调用 `future.get()` 或 `future.wait()`。**因为如果使用 `std::launch::async` 策略，其析构函数会阻塞等待任务完成**。如果不想阻塞，你需要用一个变量接收返回值（`future` 对象不会被立即析构）。
4.  **利用异常处理**：勇敢地在异步函数中抛出异常，并在主线程中用 `try-catch` 进行统一处理。

**总而言之，`std::async` 是 C++11 提供的一个“开箱即用”的异步编程利器，它极大地简化了并发任务的编写，是现代 C++ 并发编程的首选工具之一。**

# std::future

`std::future` 是 C++11 引入的 `<future>` 头库中的一个类模板。它提供了一个机制来**获取异步操作的结果**。

可以把它想象成一张 **“提货单”** 或 **“期票”**：

*   你发起了一个异步任务（比如在另一个线程里进行一项复杂的计算）。
*   这个任务不会立刻给你结果，而是立刻给你一张 `std::future` “提货单”。
*   你可以在未来的某个时候，拿着这张“提货单”去“提取”结果。如果任务还没完成，`get()` 操作会阻塞等待，直到结果就绪。

这种模型将 **“执行”** 和 **“获取结果”** 两个动作分离开，使得并发编程更加清晰和安全。

```cpp
#include <future>  // 必需的头文件

// std::future 是一个类模板
template< class T > class future;        // 通用形式
template< class T > class future<T&>;    // 引用特化
template<>          class future<void>;  // void 特化
```

## 构造函数

### 默认构造函数
```cpp
constexpr future() noexcept;  // 创建一个不共享任何状态的空 future
```
- 创建一个无效的 `future` 对象
- 调用 `valid()` 会返回 `false`

### 移动构造函数
```cpp
future( future&& other ) noexcept;  // 从另一个 future 移动构造
```
- `std::future` 是**只可移动**的类型，不可复制
- 移动后，原对象变为无效状态

### 析构函数
```cpp
~future();  // 释放资源，如果这是最后一个引用共享状态的对象，可能会阻塞
```

## 成员函数

### `operator=`
```cpp
future& operator=( future&& other ) noexcept;  // 移动赋值运算符
```
- 只能进行移动赋值，不能复制赋值
- 示例：
```cpp
std::future<int> f1 = std::async([]{ return 42; });
std::future<int> f2;
f2 = std::move(f1);  // f1 现在无效
```

### `get()`
```cpp
T get();  // 通用形式
T& get(); // 对于 T& 特化
void get(); // 对于 void 特化
```
- 获取异步操作的结果
- 如果结果未就绪，会阻塞当前线程直到结果可用
- **只能调用一次**，调用后 `future` 变为无效
- 如果异步操作抛出了异常，`get()` 会重新抛出该异常

### `valid()`
```cpp
bool valid() const noexcept;
```
- 检查 `future` 是否与共享状态关联
- 返回 `true` 表示有效（可调用 `get()`），`false` 表示无效

### `wait()`
```cpp
void wait() const;
```
- 等待结果变为可用
- 阻塞当前线程直到共享状态就绪
- 与 `get()` 不同，不返回结果，只负责等待

### `wait_for()`
```cpp
template< class Rep, class Period >
std::future_status wait_for( const std::chrono::duration<Rep, Period>& timeout_duration ) const;
```
- 在指定的超时时间内等待结果
- 返回值是 `std::future_status` 枚举：
  - `std::future_status::ready` - 结果已就绪
  - `std::future_status::timeout` - 超时，结果仍未就绪
  - `std::future_status::deferred` - 操作被延迟执行

### `wait_until()`
```cpp
template< class Clock, class Duration >
std::future_status wait_until( const std::chrono::time_point<Clock, Duration>& timeout_time ) const;
```
- 等待直到指定时间点
- 返回值与 `wait_for()` 相同

### `share()` (C++14)
```cpp
std::shared_future<T> share() noexcept;
```
- 将 `future` 的共享状态转移到一个新的 `std::shared_future` 对象
- 调用后，原 `future` 变为无效
- 允许结果被多个线程访问

## 获取 std::future

### 方式一：使用 `std::async` (最简单、最常用)

`std::async` 像一个“异步函数包装器”，它自动启动一个异步任务并返回一个 `std::future`。

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

int expensiveCalculation(int x, int y) {
    // 模拟一个耗时的计算
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return x + y;
}

int main() {
    // 使用 std::async 启动异步任务
    // std::launch::async 策略保证函数会在新线程中执行
    std::future<int> result_future = std::async(std::launch::async, expensiveCalculation, 10, 20);

    // ... 主线程此时可以继续做其他工作 ...
    std::cout << "Main thread is doing other work..." << std::endl;

    // 当我们需要结果时，使用 get() 获取
    // 如果计算还没完成，get() 会阻塞等待
    int result = result_future.get();

    std::cout << "The result is: " << result << std::endl; // 输出 30

    return 0;
}
```

`std::async` 的启动策略：
*   `std::launch::async`：强制在新线程中异步执行。
*   `std::launch::deferred`：延迟执行。直到在 future 上调用 `get()` 或 `wait()` 时，才会在主线程中同步执行函数。
*   默认策略（不指定）：可能是两者之一，由实现决定，通常会是 `async | deferred`，意味着它有权决定是异步还是延迟执行。**为了明确性，最好显式指定策略。**

### 方式二：使用 `std::promise` 和 `std::future`

这是一种更底层、更灵活的控制方式。`std::promise` 和 `std::future` 是一对相互关联的对象。
*   **`std::promise`**：**承诺**提供结果的一方。你在一个线程中通过 `promise` 对象设置值（或异常）。
*   **`std::future`**：**期望**获取结果的一方。你在另一个线程中通过与之关联的 `future` 对象来获取那个值。

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

void workerTask(std::promise<int> result_promise) {
    // 模拟工作
    std::this_thread::sleep_for(std::chrono::seconds(2));
    int result = 42;

    // 履行承诺：设置结果值
    result_promise.set_value(result);
}

int main() {
    // 创建一个 promise-future 对
    std::promise<int> my_promise;
    std::future<int> my_future = my_promise.get_future(); // 获取与 promise 关联的 future

    // 将 promise 移动给工作线程（注意：promise 不可复制，但可移动）
    std::thread worker_thread(workerTask, std::move(my_promise));

    // ... 主线程做其他事 ...

    // 获取结果
    int result = my_future.get(); // 会阻塞直到 worker_thread 中 set_value 被调用
    std::cout << "Result from thread: " << result << std::endl;

    worker_thread.join(); // 等待线程结束
    return 0;
}
```
这种方式让你可以完全控制如何以及何时传递结果，甚至可以传递异常（`set_exception`）。

### 方式三：使用 `std::packaged_task`

`std::packaged_task` 是一个类模板，它**包装了一个可调用对象（如函数、lambda表达式），并将其调用结果自动传递给一个 std::future**。它介于 `std::async` 和 `std::promise` 之间。

```cpp
#include <iostream>
#include <future>
#include <thread>
#include <chrono>

int main() {
    // 用一个 lambda 函数创建 packaged_task
    std::packaged_task<int(int, int)> task([](int a, int b) {
        std::this_thread::sleep_for(std::chrono::seconds(1));
        return a * b;
    });

    // 从 packaged_task 获取 future
    std::future<int> result = task.get_future();

    // 将任务移动到线程中执行
    // 注意：packaged_task 不可复制，必须移动
    std::thread t(std::move(task), 6, 7);

    // ... 主线程可以做其他事 ...

    // 获取结果
    std::cout << "6 * 7 = " << result.get() << std::endl;

    t.join();
    return 0;
}
```


## 示例

### 基本使用
```cpp
#include <iostream>
#include <future>
#include <thread>

int calculate() {
    std::this_thread::sleep_for(std::chrono::seconds(2));
    return 42;
}

int main() {
    // 启动异步任务
    std::future<int> result = std::async(std::launch::async, calculate);
    
    // 做一些其他工作...
    std::cout << "Doing other work..." << std::endl;
    
    // 等待并获取结果
    int value = result.get();  // 阻塞直到结果就绪
    std::cout << "Result: " << value << std::endl;
    
    return 0;
}
```

### 异常处理
```cpp
std::future<int> f = std::async([]() -> int {
    throw std::runtime_error("Error in async task!");
    return 42;
});

try {
    int result = f.get();  // 这里会抛出异常
} catch (const std::exception& e) {
    std::cerr << "Caught exception: " << e.what() << std::endl;
}
```

### 超时等待
```cpp
std::future<int> f = std::async([]{
    std::this_thread::sleep_for(std::chrono::seconds(5));
    return 100;
});

// 等待最多1秒
auto status = f.wait_for(std::chrono::seconds(1));
if (status == std::future_status::ready) {
    std::cout << "Result ready: " << f.get() << std::endl;
} else if (status == std::future_status::timeout) {
    std::cout << "Still waiting..." << std::endl;
    // 可以继续等待或做其他处理
}
```

### 使用 `std::vector<std::future>`
```cpp
std::vector<std::future<int>> futures;

// 启动多个异步任务
for (int i = 0; i < 5; ++i) {
    futures.push_back(std::async([i]{
        std::this_thread::sleep_for(std::chrono::milliseconds(100 * i));
        return i * i;
    }));
}

// 收集所有结果
for (auto& fut : futures) {
    std::cout << "Result: " << fut.get() << std::endl;
}
```

## 注意事项

1. **`get()` 只能调用一次**：调用后 `future` 变为无效
2. **异常传播**：异步操作中的异常会在 `get()` 时重新抛出
3. **析构行为**：`future` 析构可能会阻塞，直到关联的异步操作完成
4. **移动语义**：`std::future` 只能移动，不能复制
5. **生命周期**：确保 `future` 的生命周期足够长，以获取结果
6. **启动策略**：`std::async` 的默认启动策略由实现定义，可能需要显式指定

## 与其他组件的配合

`std::future` 通常与以下组件配合使用：
- `std::async` - 启动异步任务
- `std::packaged_task` - 将函数包装为异步任务
- `std::promise` - 显式设置值或异常
- `std::shared_future` - 允许多次访问结果的 future

## 总结

`std::future` 提供了一种标准化的方式来获取异步操作的结果。它的语法设计强调安全性和明确性：
- 通过移动语义防止意外的资源管理问题
- 通过一次性 `get()` 调用明确结果的消费
- 通过异常传播机制确保错误不会被忽略

# std::shared_future

由于 `std::future` 的 `get()` 方法只能调用一次，它不能被多个线程同时等待。如果需要在多个线程中获取同一个异步结果，应该使用 `std::shared_future`。

*   `std::shared_future` 是可拷贝的。
*   它的 `get()` 方法可以多次调用，返回 `const T&`（而不是移动语义）。
*   可以通过 `std::future::share()` 来获取一个 `std::shared_future`。

```cpp
std::future<int> fut = std::async(/* ... */);
std::shared_future<int> shared_fut = fut.share(); // 此时 fut.valid() 变为 false

// 现在可以将 shared_fut 复制到多个线程中使用
```

# std::thread

`std::thread` 是 C++ 标准库中用于表示和管理单个执行线程的类。它使得在 C++ 中进行多线程编程变得非常直接和方便。

首先，需要包含 `<thread>` 头文件，并且它位于 `std` 命名空间中。

```cpp
#include <thread>
using namespace std;
```

一个 `std::thread` 对象关联着一个底层的执行线程。通过提供一个**可调用对象**（函数、函数指针、Lambda 表达式、仿函数等）来创建线程，该线程会立即开始执行（具体何时开始由操作系统调度器决定）。

```cpp
std::thread thread_object(callable, arg1, arg2, ...);
```

*   `thread_object`： `std::thread` 类型的对象。
*   `callable`： 任何可以被调用的实体。
*   `arg1, arg2, ...`： 传递给可调用对象的参数。

创建线程后，必须在其销毁（析构）前决定它的命运，否则程序会调用 `std::terminate()` 终止。

## 创建线程

### 使用普通函数

这是最直接的方式。

```cpp
#include <iostream>
#include <thread>

void helloFunction() {
    std::cout << "Hello from function! Thread ID: " << std::this_thread::get_id() << std::endl;
}

int main() {
    // 创建线程 t1，并立即执行 helloFunction
    std::thread t1(helloFunction);

    // 等待线程 t1 执行完毕
    t1.join();

    std::cout << "Hello from main thread! Thread ID: " << std::this_thread::get_id() << std::endl;
    return 0;
}
```

### 使用 Lambda 表达式

Lambda 表达式非常方便，尤其适用于简单的线程任务。

```cpp
#include <iostream>
#include <thread>

int main() {
    // 使用 Lambda 表达式创建线程
    std::thread t2([](){
        std::cout << "Hello from lambda! Thread ID: " << std::this_thread::get_id() << std::endl;
    });

    t2.join();
    return 0;
}
```

### 使用仿函数（函数对象）

```cpp
#include <iostream>
#include <thread>

class HelloFunctor {
public:
    void operator()() const {
        std::cout << "Hello from functor! Thread ID: " << std::this_thread::get_id() << std::endl;
    }
};

int main() {
    HelloFunctor functor;
    std::thread t3(functor); // 也可以直接 std::thread t3(HelloFunctor());
    t3.join();
    return 0;
}
```

### 使用非静态成员函数

需要传递一个对象实例作为参数（通常是 `this` 指针）。

```cpp
#include <iostream>
#include <thread>

class MyClass {
public:

int main() {

    std::thread t4(&MyClass::memberFunction, &obj, 42);
    t4.join();
    return 0;
}
```

## 传递参数

**重要规则**：**参数总是被拷贝或移动到线程内部的私有存储中**。即使函数参数是引用，它引用的也是这个**新拷贝**，而不是原始对象。

```cpp
void printValue(int x, const std::string& s) {
    std::cout << "x = " << x << ", s = " << s << std::endl;
}

int main() {
    int num = 10;
    std::string str = "Hello";
    
    // num 和 str 都会被拷贝到线程内部
    std::thread t(printValue, num, str);
    t.join();
    
    // 修改原始变量不会影响线程内的拷贝
    num = 20;
    std::cout << "Main thread num: " << num << std::endl; // 输出 20
    return 0;
}
```

### 传递引用

如果希望线程函数修改原始变量，必须使用 `std::ref` 或 `std::cref` 来包装参数。

```cpp
void modifyValue(int& x) {
    x += 10;
}

int main() {
    int value = 5;
    // 错误：modifyValue 收到的是内部拷贝的引用，不会修改外部的 value
    // std::thread t(modifyValue, value);

    // 正确：使用 std::ref 传递引用
    std::thread t(modifyValue, std::ref(value));
    t.join();
    std::cout << "Value after modification: " << value << std::endl; // 输出 15
    return 0;
}
```

### 传递指针

传递指针时，指向的内存是共享的，需要手动确保数据竞争的安全性。

```cpp
void processArray(int* arr, size_t size) {
    // 操作数组
}

int main() {
    int data[100] = {0};
    std::thread t(processArray, data, 100);
    t.join();
    // 必须确保在 t 完成之前，data 数组不能被销毁（栈内存没问题）
    return 0;
}
```

### 移动语义（Move Semantics）

对于不可拷贝但可以移动的对象（如 `std::unique_ptr`, `std::fstream`），可以使用 `std::move` 将其所有权转移到线程中。

```cpp
void takeOwnership(std::unique_ptr<int> ptr) {
    std::cout << "Inside thread: " << *ptr << std::endl;
} // ptr 在这里被销毁

int main() {
    auto uptr = std::make_unique<int>(99);
    // 移动 uptr 到线程中，main 线程不再拥有它
    std::thread t(takeOwnership, std::move(uptr));
    
    // 此时 uptr == nullptr
    t.join();
    return 0;
}
```

## 线程生命周期
```cpp
std::thread t(函数名);  // 🚀 这一刻，子线程立即开始执行！
// ... 主线程继续执行其他代码 ...
t.join();              // ⏳ 主线程在这里等待子线程执行完成
```

- **创建线程时**：子线程**立即开始**并行执行
- **join()调用时**：主线程**阻塞等待**子线程完成
- **子线程完成时**：join()返回，主线程继续

## join() - 等待线程完成

`join()` 会阻塞当前线程（通常是主线程），直到被 `join` 的线程执行完毕。这是最常用和最安全的方式。

```cpp
std::thread t(doSomeWork);
// ... 主线程可以做其他事 ...
t.join(); // 主线程在这里等待，直到 t 完成
// t 完成后，主线程继续
```

## detach() - 分离线程

`detach()` 将子线程从 `std::thread` 对象中分离出去，让其独立地在后台运行（常被称为**守护线程**）。一旦分离，就不能再通过 `std::thread` 对象与之交互。

```cpp
std::thread t(doSomeLongRunningTask);
t.detach(); // 从此 t 不再关联任何线程，对象变为“非线程”
// 主线程继续，不等待 t
// 注意：必须确保 doSomeLongRunningTask 不会访问已销毁的局部变量！
```

**警告**： 使用 `detach` 要极其小心。如果主线程结束而分离的线程还在运行，并且它试图访问主线程栈上的变量（已销毁），会导致未定义行为（通常是崩溃）。

## 异常安全与 RAII

由于 `std::thread` 的析构函数必须要求 `join()` 或 `detach()` 被调用过，在可能抛出异常的代码中手动调用它们很危险。推荐使用 **RAII** 方式。

```cpp
#include <iostream>
#include <thread>

class ThreadGuard {
    std::thread& t_;
public:
    explicit ThreadGuard(std::thread& t) : t_(t) {}
    ~ThreadGuard() {
        if(t_.joinable()) { // 检查是否可 join（即未被 join 或 detach）
            t_.join(); // 或者根据需求改为 t_.detach();
        }
    }
    // 禁止拷贝和赋值
    ThreadGuard(const ThreadGuard&) = delete;
    ThreadGuard& operator=(const ThreadGuard&) = delete;
};

void dangerousFunction() { /* 可能抛出异常 */ }

int main() {
    std::thread t(dangerousFunction);
    ThreadGuard g(t); // 利用 RAII，无论 main 如何退出（正常或异常），g 的析构都会处理线程 t

    // ... 这里可能发生异常 ...
    // 即使发生异常，g 的析构函数也会在栈展开时被调用，从而 join 线程 t

    // 如果没有异常，main 结束时 g 的析构也会被调用
    return 0;
}
```

C++20 引入了 `std::jthread`，它的析构函数会自动 `join`，解决了这个问题。

## 其他常用成员函数

*   `joinable()`: 检查 `std::thread` 对象是否关联着一个活跃的执行线程。刚被创建、未被 `join` 或 `detach` 的对象返回 `true`。
*   `get_id()`: 获取线程的唯一标识符 `std::thread::id`。如果线程已分离或已结束，返回 `std::thread::id()`（表示“非线程”）。
*   `hardware_concurrency()`: **静态成员函数**。返回当前系统支持的并发线程数目的提示值（通常是 CPU 核心数）。常用于决定线程池的大小。

```cpp
std::thread t(doWork);
if (t.joinable()) {
    std::cout << "Thread ID: " << t.get_id() << std::endl;
    t.join();
}

unsigned int num_cores = std::thread::hardware_concurrency();
std::cout << "Number of CPU cores: " << num_cores << std::endl;
```

## 数据竞争与同步

多个线程共享数据时，会产生**数据竞争**（Data Race）。必须使用同步原语来保护共享数据。

### 使用互斥量 (Mutex)

`std::mutex` 是最基本的同步原语。

```cpp
#include <iostream>
#include <thread>
#include <mutex>

std::mutex g_mutex;
int shared_data = 0;

void safeIncrement() {
    for (int i = 0; i < 100000; ++i) {
        std::lock_guard<std::mutex> lock(g_mutex); // 构造时加锁，析构时自动解锁 (RAII)
        ++shared_data;
    } // lock 在这里析构，自动释放锁
}

int main() {
    std::thread t1(safeIncrement);
    std::thread t2(safeIncrement);

    t1.join();
    t2.join();

    std::cout << "Final value: " << shared_data << std::endl; // 保证是 200000
    return 0;
}
```

### 其他同步工具

*   `std::unique_lock`: 比 `std::lock_guard` 更灵活，可以手动加解锁。
*   `std::condition_variable`: 用于线程间的条件同步。
*   `std::atomic`: 提供原子操作，无需锁即可安全地对基本数据类型进行并发访问。

```cpp
#include <atomic>
std::atomic<int> atomic_data(0);
void fastIncrement() {
    for (int i = 0; i < 100000; ++i) {
        ++atomic_data; // 原子操作，线程安全
    }
}
```

## 总结与最佳实践

1.  **明确线程命运**： 在 `std::thread` 对象析构前，必须调用 `join()` 或 `detach()`。
2.  **优先使用 `join()`**： `detach()` 使用场景有限且危险，除非你非常清楚自己在做什么。
3.  **使用 RAII**： 利用类似 `ThreadGuard` 的包装器或 C++20 的 `std::jthread` 来确保异常安全。
4.  **小心传递参数**： 默认是值拷贝。需要传引用时用 `std::ref`，移动资源时用 `std::move`。
5.  **警惕数据竞争**： 任何对非只读共享数据的访问都必须通过同步机制（互斥锁、原子操作等）进行保护。
6.  **管理线程数量**： 使用 `std::thread::hardware_concurrency()` 作为参考，避免创建远超核心数量的活跃线程。

通过 `std::thread`，C++ 将多线程编程无缝地集成到了语言中，使其变得类型安全且易于使用，是现代 C++ 并发编程的基石。
